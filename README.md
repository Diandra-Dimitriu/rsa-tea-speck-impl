# Advanced Cryptography CLI Implementation

A command-line application suite written in C that implements modern symmetric and asymmetric cryptographic algorithms from scratch. It features standalone, byte-level file processing for TEA, Speck, and RSA, reading data (text or binary) via a flexible CLI, encrypting or decrypting it, and securely outputting the result.

---

## Algorithm Overview

### TEA (Tiny Encryption Algorithm)
A symmetric block cipher utilizing a Feistel-like structure. It operates on 64-bit blocks with a 128-bit key across 32 rounds. The security relies heavily on a "magic constant" derived from the golden ratio, combined with bitwise shifts, additions, and XOR operations. Our implementation utilizes Cipher Block Chaining (CBC) mode to securely handle multi-block files.

### Speck (Speck64/128)
A lightweight symmetric block cipher developed by the NSA. It is an ARX (Add-Rotate-XOR) cipher, meaning its security stems entirely from the non-linear mixing of modular addition, bitwise rotations, and XORs, without needing substitution boxes (S-boxes). This implementation operates on 64-bit blocks with a 128-bit key and also leverages CBC mode for secure file processing.

### RSA (Rivest–Shamir–Adleman)
An asymmetric-key cryptosystem based on the mathematical difficulty of factoring large prime numbers. Unlike the symmetric ciphers, it uses a public key for encryption and a private key for decryption. This implementation relies on the GNU Multiple Precision Arithmetic Library (GMP) to handle the massive integers (1024-bit+) required for modern security standards, and features custom byte-alignment padding to prevent data loss during mathematical conversions.

---

## Implementation Approach

* **Binary File I/O:** The applications open files using `"rb"` (read binary) and `"wb"` (write binary) modes. This ensures the programs can safely process any file type (documents, images, or executables) without corrupting newline characters or metadata.
* **Chunking and Streaming:** Instead of loading entire files into memory, the symmetric programs read data in 8-byte chunks (matching the block size), processing and writing them sequentially. This enables the encryption and decryption of files larger than 4 GB with minimal memory overhead.
* **Flexible CLI:** The programs loop through the `argv` array to parse command-line arguments manually. This makes the interface order-independent, allowing operational flags, keys, and filenames to be typed in any sequence.

## Compilation Instructions

To compile the applications, you need a C compiler (like GCC) installed on your system. 

> **Note:** The RSA implementation requires the GMP library to be installed on your machine.

Open your terminal, navigate to the folder containing the source code, and run the following commands:

**Compile TEA:**
```bash
gcc tea.c -o tea
```
**Compile Speck:**
```bash
gcc speck.c -o speck
```
**Compile RSA:**
```bash
gcc RSA.c -o rsa -I C:\msys64\mingw64\include -L C:\msys64\mingw64\lib -lgmp
```

## Example Usage

The applications require four main components to run successfully:

* **Operation Mode:** `-e` to encrypt or `-d` to decrypt.
* **Input File:** The target file you want to process.
* **Key File:** The file containing the secret key, preceded by the `-k` flag.
* **Output File:** The destination file, preceded by the `-o` flag.

### Encrypting a File

To encrypt a file named `plain.txt` using a key file named `key.txt`, and save the scrambled binary output to `cipher.bin`:

```bash
./speck -e plain.txt -k key.txt -o cipher.bin
```

### Decrypting a File

To decrypt the file cipher.bin using the same key file, and save the decrypted output to decrypted.txt:

```bash
./speck -d cipher.bin -k key.txt -o decrypted.txt
```

Attached in the repository is a set of test environments. For each algorithm (TEA, Speck, RSA), there are 3 specific test cases provided. These include:

* **Sample input files.**
